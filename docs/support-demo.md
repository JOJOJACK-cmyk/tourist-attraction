# 자율 후원 화면 · 모의 결제

공개 페이지 하단 **커피 한 잔으로 응원하기 ☕**에서 창을 열거나 `/support`에 접속합니다. 로그인 없이 1,000·3,000·5,000원의 테스트 금액을 선택하고 **완료해 보기**, **취소하기**, **실패 상황 보기**를 누릅니다.

이 기능은 포트폴리오용 **로컬 모의 후원**입니다. 실제 결제사 테스트 서버 연동, 카드 승인, 송금, 환불, 실제 후원금 수집을 구현한 것이 아닙니다. 카드·계좌 정보는 입력하거나 저장하지 않습니다. 모든 공개 화면과 API 응답에서 DEMO임을 표시하고, 모의 금액을 실제 후원 통계로 노출하지 않습니다. 게시판과 채팅 사용 권한에 영향을 주지 않습니다.

## 구조

| 항목 | 동작 |
| --- | --- |
| POST /api/support/orders | amount·UUID requestId로 모의 주문 생성 |
| GET /api/support/orders/{id} | 같은 세션의 모의 결과 조회 |
| POST /api/support/orders/{id}/result | SUCCESS·CANCEL·FAIL 결과 체험 |
| support_demo_order | 모의 금액·상태·생성/완료 시각·세션 소유 키·중복 방지 키 |

상태는 READY → SUCCEEDED/CANCELLED/FAILED이며 20분이 지나면 EXPIRED로 처리합니다. 종료 상태에서 다른 결과로 바꿀 수 없습니다. 같은 생성 요청의 중복은 같은 주문을 반환하고, 같은 결과 재요청은 같은 결과를 반환합니다. 요청 키를 재사용하면서 금액을 바꾸면 거부합니다. 결과 요청에서 전달한 금액은 사용하지 않고 서버에 저장된 금액을 반환합니다.

세션 소유 키는 서버에서 생성하며 응답에 노출하지 않습니다. 다른 세션은 주문 ID를 알아도 조회·결과 변경을 할 수 없습니다. 로그인/회원가입의 세션 ID 변경에는 같은 소유 키가 유지되지만 로그아웃·세션 만료 후에는 이전 결과를 다시 조회할 수 없습니다. 익명 체험을 위해 회원 데이터와 연결하지 않습니다. POST에는 Spring Security CSRF 토큰을 사용하고 각 요청 전 현재 세션의 토큰을 다시 가져옵니다.

창을 닫는 동작 자체는 후원 취소 확정이 아닙니다. 확인 단계에서 **취소하기**를 눌러야 CANCELLED가 기록되며, 닫아둔 READY 주문은 만료될 수 있습니다. 페이지를 새로고침하면 브라우저의 현재 체험 상태는 초기화됩니다. 결제창 단계에서는 닫고 다시 열면 같은 주문을 조회합니다. 테스트 주문 데이터는 DB에 저장되며 자동 삭제는 하지 않습니다.

## 확인

- 새로운 외부 API 키나 결제사 계정은 필요하지 않습니다.
- 기존 MySQL에서는 JPA update로 support_demo_order 테이블이 추가됩니다.
- 서버 테스트: 공개 화면·CSRF·허용 금액·서버 금액 유지·중복 요청·세션 격리·종료 상태·만료.
- 화면 테스트: `node src/test/js/support.test.cjs`.
- 실제 MySQL과 브라우저 렌더링은 사용자 환경에서 추가 확인합니다.

실제 후원을 열 때는 별도로 외부 후원 링크 또는 결제사 연동을 선택해야 합니다. 현재 /result API는 사용자가 모의 결과를 선택하는 데모 전용 엔드포인트라 실제 결제 승인 용도로 사용할 수 없습니다.
