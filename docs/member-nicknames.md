# 회원 닉네임

## 설정

일반 회원가입 화면(`/login?mode=signup`)에서 닉네임을 선택 입력할 수 있습니다. 기존 가입 API와 커뮤니티·채팅·방문 후기 화면의 간편 가입은 닉네임 없이도 동작합니다. 로그인 후 주요 메뉴 **내 계정 → 내 프로필 → 닉네임 저장**에서 설정·변경합니다. 네이버·구글 회원도 같은 화면을 사용합니다. 소셜 제공자의 실명·이메일·별명을 자동으로 닉네임으로 가져오지 않습니다.

닉네임은 한글 음절·영문·숫자·밑줄 2~16자입니다. 양끝 공백을 제거하고 NFKC로 정규화한 뒤 표시용 이름과 소문자 비교 키를 저장합니다. 대소문자·전각 문자 차이로 같은 이름을 중복 등록할 수 없습니다. 자기 이름의 대소문자만 바꾸는 것은 허용합니다. `익명`은 예약된 이름이며 일반 회원은 `admin`, `administrator`, `관리자`, `운영자`, `여행온도`도 사용할 수 없습니다.

## 표시 기준

| 위치 | 표시 |
|---|---|
| 커뮤니티 게시글·댓글 | 현재 회원 닉네임, 미설정 회원은 `익명` |
| 채팅방 생성·참여 | 닉네임을 기본 별명으로 입력, 방별로 변경 가능 |
| 기존 채팅 참여 별명·이전 메시지 | 저장된 방별 이름을 유지 |
| 직접 방문 후기·관광지 후기 집계 | 기존 익명 표시 유지 |
| 자신의 로그인 상태·내 프로필 | 닉네임 우선, 미설정 시 기존 계정 표시 |

닉네임을 바꾸면 기존 커뮤니티 글·댓글도 다시 조회할 때 새 이름으로 표시됩니다. 글·댓글의 소유권과 채팅 권한은 변경하지 않습니다. 공개 응답에 로그인 ID나 내부 닉네임 비교 키를 넣지 않습니다. 닉네임이 없는 계정의 로그인 ID를 공개 이름으로 사용하지 않습니다.

## API·저장

`POST /api/auth/signup`은 선택 `nickname` 필드를 받습니다. `GET /api/auth/me`는 자기 계정의 `nickname`(미설정 시 빈 문자열)과 `displayName`을 제공합니다. `PATCH /api/auth/profile`은 로그인·CSRF가 필요하며 `{"nickname":"봄여행자"}`만 사용해 현재 로그인 회원의 이름을 변경합니다. 회원 ID·역할·로그인 ID·비밀번호를 변경하는 API가 아닙니다. 중복은 409, 입력 형식 오류는 400으로 반환하고 기존 닉네임은 유지합니다.

기존 `community_member` 테이블에 nullable `nickname`, nullable unique `nickname_key`가 추가됩니다. JPA `ddl-auto=update` 설정으로 서버 시작 시 적용되고 기존 회원·게시글은 유지됩니다. DB 고유 제약도 적용해 동시에 같은 이름을 저장하는 경우 중복을 차단합니다.

검증: `NicknameIntegrationTest`에서 가입·선택 입력·정규화·중복·예약어·로그인·CSRF·본인 변경·소셜 회원·게시글 및 댓글 표시·직접 후기 익명을 확인합니다. 로그인 페이지, 커뮤니티, 채팅 자바스크립트 테스트에서 닉네임 입력·저장·오류 보존·표시·기본 참여 이름을 확인합니다.
