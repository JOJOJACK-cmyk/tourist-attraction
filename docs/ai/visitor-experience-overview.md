# 방문 경험을 비용·서비스·혼잡으로 종합하기

## 이용자가 얻는 정보

| 분야 | 종합할 경험 | 섞지 않을 내용 |
|---|---|---|
| 식비 | 저렴/보통/비쌈 체감, 양·구성 대비 만족, 소량 포장 선택 | 맛 칭찬을 가격 만족으로 바꾸기 |
| 시장 주변 숙박비 | 실제 예약·이용한 숙소 비용 체감과 예약 조건 | 청결·위치 만족을 가격 만족으로 바꾸기, 고성·양양 숙소 |
| 서비스·응대 | 실제 친절·불친절·설명·문제 처리 | 빠른 회전, 시장 밖 업체 응대 |
| 혼잡·대기 | 시장 통로, 점포 줄, 주차 대기를 시간대와 함께 | 한 가게의 줄을 시장 전체의 상시 혼잡으로 바꾸기 |

카드는 한 줄 분위기, 긍정/부정/그 외 체감 언급 수, 주요 경험과 실제 언급 조건을 보여줍니다. 같은 후기가 여러 경험을 말해도 해당 분야·감정에서 한 번만 셉니다. 맛만 칭찬한 글은 식비 카드에 들어가지 않습니다. 숙박 가격 후기가 없으면 숙박비 부족으로 남습니다. 1~2건은 개별 경험이며 3건 이상도 검토된 글의 반복 언급일 뿐 지역 대표 통계가 아닙니다.

기존 검토 요약에서 직접 경험 여부를 원문으로 재확인하지 않은 항목은 unclear입니다. 이 항목은 검토된 언급으로 활용되지만 직접 방문자 수로 표현하지 않습니다. 새 공개 본문 확인 자료는 예시에서 우선 표시합니다. 가격 카드의 긍정은 저렴함 또는 비용 대비 만족을 뜻하며 현재 가격표가 아닙니다.

## 그라운딩 검색

기존 Gemini Search 클라이언트를 네 분야로 분리했습니다. 분야마다 관광지 별칭/연도를 넣어 gall.dcinside.com, fmkorea.com, theqoo.net 사이트 검색과 일반 방문 후기 검색을 요청합니다. 긍정·부정 검색을 보완하되 중립 방문 후기를 먼저 찾도록 합니다. 대포항·오징어난전 같은 제외 장소는 기존 관광지 설정으로 전달합니다.

- 한 조회에서 네 개의 generateContent + google_search 요청을 병렬 전송합니다. 같은 앱 인스턴스에서는 한 검색 묶음만 실행하고 추가 요청은 429로 제한합니다.
- 요청 검색어는 모델에게 주는 계획입니다. 실제 실행 검색어는 groundingMetadata.webSearchQueries입니다. 계획을 줬다고 그 사이트를 실제 검색·열람했다고 보장하지 않습니다.
- 응답의 groundingSupports가 실제 답변 문장과 groundingChunks의 안전한 HTTPS 출처에 연결된 내용만 게시합니다. 인용 없는 원문 답변 부분은 요약으로 노출하지 않습니다.
- 분야별 실패(failed)와 인용 근거 부족(insufficient)을 구분합니다. 실패한 분야를 한산/친절/저렴하다고 바꾸지 않습니다.
- 출처 링크 수는 방문자 수나 후기 수가 아닙니다. 자동 검색 결과에서 칭찬/불만 건수를 생성하지 않습니다. 직접 경험 건수는 개별 본문을 확보·추출·중복 제거한 후에만 계산합니다.
- 참고 링크는 접어서 보여주며 Google 검색 제안 HTML은 스크립트·동일 출처 권한 없는 sandbox iframe에 표시합니다.
- Gemini 검색 연결은 GEMINI_API_KEY가 필요합니다. 이번 자동 테스트는 가짜 HTTP 검색 API로 검증했으며 실제 키 검색 성공을 뜻하지 않습니다. 한 조회에 API 요청 4건이 발생합니다.
- Ollama/Gemma는 받은 본문 추출용입니다. 인터넷 검색 기능을 자동으로 제공하지 않습니다. 프롬프트는 prompts/review-extraction-system.txt와 prompts/visitor-search-system.txt에 있습니다.

Google grounding은 모델 답변과 링크의 연결 정보를 주지만, 모든 페이지 본문·방문일·작성자 독립성의 검증 결과를 주는 수집 DB가 아닙니다. 단순히 링크가 있다는 이유로 30명의 경험을 읽었다고 표현하지 않습니다. 작성일·장소·직접 경험 판별은 원문 검토 또는 후속 본문 추출 단계에서 별도로 확인해야 합니다.

## 검증

서버 테스트는 네 분야 요청, 사이트 검색 계획/실행 정보 분리, 부분 실패/자료 부족, 공유 출처 ID 연결, 인용 없는 주장 제외를 검증합니다. UI 테스트는 연도 격리, 같은 글 URL 변형 중복 제거, 재게시 제외, 맛/가격 구분, 서비스·숙박 공백, 안전한 검색 제안 렌더링을 검증합니다. 실제 계정으로 외부 검색을 호출하거나 브라우저 시각 검증을 수행한 결과는 아닙니다.
